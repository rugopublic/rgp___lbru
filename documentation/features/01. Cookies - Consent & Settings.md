# Документация по функционалу Cookies

## 1. Сервис `CookieConsentService`

**Описание:** Сервис отвечает за чтение, обновление и валидацию согласий пользователя на использование cookies.  

**Основные методы:**

- `readForGuest($cookie)` — чтение согласий для гостя из cookie. Возвращает массив с ключами: `required`, `functional`, `marketing`.
- `readForUser(User $user)` — чтение согласий для зарегистрированного пользователя через отношение `cookieSettings`.
- `updateForGuest(array $settings)` — подготовка и валидация входных данных от гостя. Не сохраняет.
- `updateForUser(User $user, array $settings)` — применение согласий пользователя через методы модели `UserCookieSettings`.
- Валидация: `required` всегда true, исключение при попытке отозвать обязательные cookies. Optional куки кастятся к boolean.

**Покрытие тестами:**

- Чтение согласий для гостя и пользователя.
- Обработка null, пустых или неверных значений.
- Применение изменений для гостя и пользователя.
- Соблюдение правил бизнеса (required всегда включены).
- Валидация и приведение типов.

## 2. FormRequest `UpdateCookieConsentRequest`

**Описание:** Форм-реквест для POST `/cookies`. Подготавливает входные данные для сервиса.

**Особенности:**

- Метод `prepareForValidation` кастит входные значения в boolean.
- Обеспечивает значения по умолчанию для отсутствующих ключей.
- Validation rules:
  ```php
  [
      'required'   => 'sometimes|accepted',
      'functional' => 'sometimes|boolean|nullable',
      'marketing'  => 'sometimes|boolean|nullable',
  ]
  ```

**Тесты:**

* Кастинг всех типов входных данных (`1`, `0`, `'true'`, `'false'`, `null`, `''`) в boolean.
* Проверка правил валидации.
* Обеспечение корректной работы с отсутствующими ключами.

## 3. Контроллер `CookieController`

**Описание:** Отвечает за GET/POST маршруты `/cookies`.

**Методы:**

* `settings()` — отдаёт страницу настроек cookies с текущими значениями.
* `update(UpdateCookieConsentRequest $request)` — обрабатывает POST-запрос, применяет согласия и отображает страницу подтверждения.

**Тесты:**

* Unit-тесты методов контроллера без HTTP.
* Проверка вызова методов сервиса и правильной передачи `$settings`.

| Метод | URI      | Имя              | Доступ           |
| ----- | -------- | ---------------- | ---------------- |
| GET   | /cookies | cookies.settings | Все пользователи |
| POST  | /cookies | cookies.update   | Все пользователи |

**Тесты:**

* Проверка существования и правильного назначения методов контроллера.
* Проверка HTTP методов и именованных маршрутов.
* Проверка доступности для гостей и авторизованных пользователей.
* Проверка URL структуры и отсутствия обязательных параметров.

## 5. Вьюхи

**1. `settings.blade.php`**

* Используется переменная `$settings` с ключами `required`, `functional`, `marketing`.
* Отображает чекбоксы для всех категорий куки.
* Тесты:

    * Рендеринг без ошибок.
    * Корректная передача `$settings`.
    * Чекбоксы соответствуют входным данным.

**2. `updated.blade.php`**

* Использует `$settings` для отображения итоговых статусов.
* Показывает сообщение об успешном обновлении.
* Тесты:

    * Рендеринг без ошибок.
    * Корректное отображение статусов (enabled/disabled) для всех категорий.

* Проверка наличия всех ключей в каждой локализации.

**Примечания:**

* `$settings` всегда должен передаваться в вьюхи.
* Обязательные cookies (`required`) не могут быть отключены.
* Все optional cookies могут принимать значения `true/false/null`.
* Рекомендуется поддерживать единообразие структуры ключей в локализациях при добавлении новых языков.
